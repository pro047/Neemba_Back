## 4. 2026-08-02 주일예배 관측 기록

**서버측 장애 0건.** 발생한 문제는 전부 ① 기기측 네트워크 ② 미배포 코드로 인한
오탐·기록 결함이다.

| 항목 | 결과 |
|------|------|
| 번역 총량 | 약 550건 (10:51~11:27 KST, 37분) |
| 순단 | **3회 — 전부 close_code 1006**(기기측 비정상 단절) |
| 자막 유실 | 1회차 0건 / 2회차 **span 5개** (세션 5회 교체 중) |
| 번역 품질 | 정상. 찬양 구간 단어 파편화 외 문장 잘림·중복·빈 문자열 없음 |
| ffmpeg·NATS·컨테이너·5xx | 전부 정상 (`ffmpeg_stale` 증분 0) |

### 4-1. 순단 3회 — handover §4-7 가설 ① 쪽 근거가 쌓였다

```
02:02:17 → 02:02:18 UTC   1초,  flushed 4,  유실 0   (정상 복구)
02:13:20 → (재연결 없이 02:13:27 세션 종료)          → 세션 5회 교체로 이어짐
02:27:36 → (재연결 없음, keepalive 300s 타임아웃)     → 예배 종료
```

**7/26 예배 순단 3회도 전부 1006 이었다.** 두 예배 연속으로 1001(기기 정상 종료)이
한 건도 없다는 것은 절전·백그라운드 전환(가설 ②)보다 **네트워크 불안정(가설 ①)**
쪽을 가리킨다. 다만 §4-7 이 제안한 현장 조치(Wi-Fi↔LTE 전환 비교)는 아직 미수행이라
확정은 못 한다.

### 4-2. 세션 5회 교체 — **원인 미확인**

```
02:13:27  세션 2d3aa2ab 종료 (끊긴 지 7초 만에 = 명시적 stop 호출)
02:13:27  → ca1e261b  (21초 후 종료)
02:13:48  → d4039f1b  (48초 후 종료)
02:14:37  → fd6ae34b  (96초 후 종료)
02:16:13  → e01b46f0  ( 8초 후 종료)
02:16:21  → 0d79c3ef  ← 안정화
```

각 종료마다 `publish buffer: span dropped after stop` 이 찍혀 **총 5개 span 이
유실**됐다. keepalive 는 300초까지 기다리게 돼 있는데 7초 만에 `stopped` 가 찍혔으니
서버가 죽인 것이 아니라 **명시적 stop 호출**이다.

**사용자 확인 결과: 본인이 한 것이 아니다.** 현장 다른 조작인지 자막 앱의 재기동
루프인지 미확정. 다음 예배에서 같은 패턴이 재발하는지 관찰할 것.

  판단은 diff 가 아니라 배포 파이프라인 기준으로. **송출 중에는 release 를 머지하지 말 것.**
- **자산 반영 확인은 "소스에 그 문자열이 있는가" 로 할 것 (2026-08-05 실패에서).**
  동작의 부수 효과로 버전을 역추론하면 안 된다. 실제로 겪은 오류:
  `closest('.table-wrap').scrollHeight === parentElement.scrollHeight` 로 신·구 버전을
  가르려 했는데, `scrollHeight` 는 레이아웃 값이고 app.js 는 `scrollTop` 만 대입하므로
  **어느 버전이든 항상 같은 값이 나온다.** 쓸 수 있는 형태:

  ```js
  fetch('app.js', {cache: 'reload'}).then(r => r.text()).then(t => console.table({
    '배너 DOM (index.html)':     !!document.getElementById('detail-new'),
    '스크롤 대상 교정 (app.js)':  t.includes('closest(".table-wrap")'),
  }));
  ```

  DOM 검사는 **지금 페이지가 실행 중인 버전**을, `fetch` 는 **서버가 주는 버전**을
  본다. 둘이 갈리면 캐시다. 서버만 단독 확정하려면 SSH 로
  `md5sum /var/www/html/monitor/app.js` 를 리포 파일과 대조한다(브라우저를 안 탄다).
