# 앱 진단 기록 업로드 계약 (client-diagnostics M1)

mvp(앱) 세션이 이 문서만 보고 구현할 수 있도록 설계 §4를 옮긴 것이다. 정본 계획: `docs/client-diagnostics-plan.md`.

## 엔드포인트

`POST https://neemba.app/api/diagnostics/client-logs` · `Content-Type: application/json` · 인증 없음.

## 요청 본문

```json
{
  "installId": "3f1c2a9e-7b4d-4e2a-9c1f-0a2b3c4d5e6f",
  "appVersion": "1.4.2+37",
  "entries": [
    {"seq": 1041, "line": "2026-11-15T02:09:00.123Z ws_close code=1006 reason=<empty>"},
    {"seq": 1042, "line": "2026-11-15T02:09:00.988504Z ws_retry attempt=1"}
  ]
}
```

- `installId`(필수): 최초 실행 시 만든 UUID 문자열. 대소문자는 구분하지 않는다(서버는 소문자로 저장).
- `appVersion`(선택): 64자 이하.
- `entries`(필수, 1개 이상): `seq`는 0 이상의 JSON 정수이고 설치 ID 안에서 단조 증가한다. `line`은 기기 기록 한 줄의 원문이며 빈 문자열은 허용하지 않는다.
- 배치 안의 순서는 상관없다. 같은 seq가 두 번 있으면 첫 번째만 저장한다.
- **앱이 업로드 전에 URL 마스킹을 적용한다**(sessionId가 든 전체 URL이 줄에 남지 않게). 서버는 검사하지 않는다.
- 줄 머리는 `<ISO8601 시각(타임존 필수)> <event> ...` 형태를 권장한다. 서버는 앞 두 토큰만 따로 파싱해 두고, 파싱에 실패해도 원문은 저장한다.

## 상한 — 개수와 바이트는 각각 따로 적용된다

| 항목 | 서버 상한 | 넘으면 |
|---|---|---|
| 요청 본문(직렬화된 UTF-8 바이트) | 2,097,152 (2 MiB) | 413 |
| entries 개수 | 10,000 | 413 |
| line 길이 | 4,000자 | **잘라서 저장**하고 응답 `truncated`에 집계 |

**앱의 배치 분할 규칙(권장, 두 조건을 모두 지킨다):** 한 요청의 entries는 **5,000개 이하**, 직렬화한 본문은 **1 MiB 이하**로 맞춘다. 두 조건 중 하나라도 넘으면 나눈다.

- 기기 보관량(256KB × 2)이 한 요청에 들어간다는 보장이 없다. 짧은 줄은 개수 상한에, 이스케이프되는 문자가 많은 줄은 바이트 상한에 먼저 걸린다. 보관분 전체를 한 요청에 넣으면 413이 날 수 있으므로 분할은 필수다.
- 줄 안의 U+0000과 짝 없는 서로게이트는 서버가 U+FFFD/`?`로 바꿔 저장한다. 거부하지 않는다.
- 참고(추정): 최소 줄(약 27바이트) 기준 보관분은 약 19,418줄이고, 직렬화 방식에 따라 약 0.99–1.07 MB다.

## 응답

| 코드 | 의미 | 앱 동작 |
|---|---|---|
| 200 | 저장됨(중복 포함). 본문 `{"ackedMaxSeq": <요청 entries의 최대 seq>, "inserted": n, "duplicates": n, "truncated": n}` | 이 배치의 seq를 모두 업로드 완료로 표시하고 `ackedMaxSeq`로 "어디까지 올렸나"를 갱신한다 |
| 413 | 너무 큼 | **같은 배치를 재전송하지 않는다.** 더 작게 나눠서 보낸다 |
| 422 | 형식 오류(JSON 아님, installId가 UUID 아님, seq가 음수이거나 정수가 아님, entries가 비었음, line이 빈 문자열, appVersion이 64자 초과) | **재전송하지 않는다.** 앱 버그로 보고 해당 배치는 버린다(업로드 완료로 표시) |
| 429 | 레이트 제한(nginx) | 다음 업로드 시점에 재시도한다. 미전송분은 유지한다 |
| 502 / 503 / 504 / 타임아웃·네트워크 오류 | 서버 일시 실패. **저장 여부는 불확실하다**(저장됐을 수도, 안 됐을 수도 있다) | 다음 업로드 시점에 같은 배치를 재전송한다. 미전송분은 유지한다. 서버가 `(installId, seq)`로 멱등 처리하므로 중복 행은 생기지 않는다 |

- 200은 DB 문장이 성공한 뒤에만 응답한다. 200을 받은 seq는 서버에 있다.
- 413·429 본문은 nginx HTML일 수 있다. **앱은 상태 코드만 보고 판단한다.**
- 레이트 제한: IP당 분당 60회, 순간 여유 40회.
- 서버가 만드는 413·422·503 본문은 `{"detail": "<고정 문구>"}`다.

## 서버가 하는 일과 하지 않는 일

- 줄 원문을 통째로 저장한다. 맨 앞 시각(`client_ts`, UTC로 변환)과 두 번째 토큰(`event`, 1–64자)만 따로 파싱해 둔다.
- k=v 필드는 파싱하지 않는다.
- `(installId, seq)`가 같으면 1행만 남긴다(멱등).
- seq 빈 구간(기기 회전으로 사라진 기록)을 서버가 메우지 않는다. 조회하면 빈 구간으로 드러난다.
- 클라이언트 IP는 저장하지 않는다.
- 기기 총량·일별 총량 상한과 보존 스윕은 M1에 없다.
